# CloudCare 云栈——企业客服知识库问答系统

**项目性质：**个人工程项目，基于合成业务资料开发与评测  
**技术栈：**Python、BM25、倒排索引、JSONL、HTTP API、HTML/CSS/JavaScript  
**项目地址：**https://github.com/Mysarff/service

## 项目背景

面向企业客服中产品资料分散、用户问法不统一、故障处理步骤难以快速定位等问题，围绕账号权限、订单售后、订阅账单等16个业务模块，构建支持知识导入、带出处问答和本地工单记录的客服知识库原型，提供从问题检索到处置资料定位的统一入口。

## 项目职责与技术亮点

1. **知识构建与可追溯入库：**整理112份合成业务文档，按模块章节和故障处理阶段组织为592个检索片段，保留来源、版本和父子关联；实现TXT/Markdown分段导入、内容哈希去重与SHA-256完整性校验。
2. **Query归一与上下文补全：**对口语时间表达进行规则化归一，结合上一轮问题补全短追问，支持最近两轮对话上下文；结合业务模块筛选与关键词加权组织候选资料。
3. **检索排序与场景扩展：**基于BM25融合标题、标签和业务模块权重，围绕96个故障场景实现同场景分组与同源子段扩展，按“定位、处置、验收、升级”选择对应章节，减少相邻章节挤占检索结果的问题。
4. **索引与检索性能优化：**构建词项倒排表定位候选片段，缓存词频、IDF及文档统计量；保留全量扫描作为对照，完成640次排名与分数一致性检查，验证候选裁剪前后结果一致。
5. **回答容错与评测：**实现兼容模型调用接口、来源ID校验、证据不足提示及模型异常原文回退；构建88题开发回归集、15项功能检查和并发测试脚本，保存逐题失败、逐请求耗时及代码与数据哈希。

## 项目成果

- **检索效果：**在64道有依据的自建开发回归题上，Top-1命中率由基础BM25的71.9%提升至89.1%（提高17.2个百分点），Hit@5为100%；24道无依据或越界回归题全部返回限制说明。
- **检索效率：**在592片段、64题×10轮的同条件对照中，平均检索耗时由1.475 ms降至1.074 ms，下降27.2%，640/640次排名及分数一致。
- **功能与接口：**15项功能检查全部通过；完成1、4、8并发各2,000次本机短时接口请求，HTTP成功率100%，8并发原文检索模式P95为21.58 ms。

## 面试解释与指标口径（不必整段放入简历）

- 以上数字来自2026-09-27的实测记录；2026-09-29核对时，当前核心代码哈希与该记录一致。本次是材料核对，没有重新跑性能测试。
- 项目是合成数据上的个人工程原型。592是检索片段数，4,736条FAQ问法和24,000条模拟工单复用已有知识，不代表新增独立事实；未接入真实企业客户。
- Query处理是少量领域表达规则与短追问的历史问题拼接，没有实现基于LLM的通用改写、HyDE或子查询分解，也没有单独评测Query改写带来的增益。
- 当前在线检索为增强BM25。TF-IDF、基础BM25、增强BM25是分别运行的对照方法，没有融合成双路召回。全量扫描与倒排候选也是同一检索方法的两条实现路径，不是稠密/稀疏混合检索。
- 场景扩展通过parent_id选择同源阶段子段，不等于语义切分、父文档全文回取或神经重排。
- 64道正例和24道负例参与过调试，属于开发回归集，不是独立盲测。Top-1仍有7题失败。71.9%到89.1%是多个规则组合的对照结果，不能将全部增益归因于Query归一或某一个组件。
- 27.2%是平均检索耗时的相对下降，计算为(1.475-1.074)/1.475；17.2是命中率提高的百分点，两者单位不同。
- 并发测试关闭外部模型，每组约5至7秒，属于本机短时测量。P95不代表最慢请求；8并发最大耗时约1.03秒，HTTP成功也不等于答案正确。
- 兼容模型接口与失败回退已实现；现有记录中真实模型因无效凭据未完成验收，不能宣称已验证生成准确率、RAGAS得分或LLM端到端延迟。
- 当前没有实现Milvus、BGE、BERT、LangChain、Redis、MySQL、FastAPI、OCR、LoRA或生产多租户鉴权。教育版和参考案例中的技术栈与指标不能直接用于本客服版。

## 证据位置

- `engine.py`：查询归一、短追问补全、BM25、倒排表、场景分组、来源校验和异常回退。
- `data/manifest.json`：来源文档、知识片段、FAQ与模拟工单数量。
- `evaluation/benchmark_summary.json`：测量环境、代码/语料/题目哈希、三种排序方法、检索和HTTP计时。
- `evaluation/benchmark_results.json.gz`：逐题排名与逐请求原始记录。
- `evaluation/system_results.json`：15项功能检查结果。
- [BENCHMARK.md](BENCHMARK.md)：指标定义、首次失败、最终结果及复测命令。
