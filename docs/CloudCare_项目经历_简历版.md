# CloudCare 云栈——企业客服 RAG 知识库问答系统

**项目性质：**个人工程项目，使用合成业务资料开发与评测

**技术栈：**Python、FastAPI、LangChain、Milvus、BGE-M3、BGE-Reranker、BERT、Qwen API、BM25／RRF、MySQL、Redis、RapidOCR、Docker

**项目地址：**[Mysarff/service](https://github.com/Mysarff/service)

## 项目背景

针对企业客服资料分散、用户表达不统一、故障处理步骤难以定位等问题，围绕账号权限、订单售后、账单订阅及开放接口等16类业务知识，构建支持多格式资料入库、连续咨询、带出处问答和工单留存的客服知识库原型，将文档解析、混合检索、证据回答与问题交接串成完整流程。

## 项目职责与技术亮点

1. **知识构建与持久化：**按章节及故障处理阶段整理112份合成业务文档、592个可追溯知识单元；实现TXT／Markdown／PDF／Office／图片解析及RapidOCR识别，对新上传资料使用LangChain递归父子分块，保存来源、页码、版本、SHA-256和父子关系；以MySQL单事务发布上传资料，核对向量与正文一致性，异常时按新片段ID回滚索引。
2. **Query理解与意图路由：**基于中文BERT冻结骨干训练三类客服分类头，使用2,304条合成样本进行分组划分；结合服务端会话补全短追问，通过Qwen改写口语查询并校验编号、阿拉伯数字及常见否定表达，为知识咨询、人工诉求及范围外问题选择处理路径。
3. **双路召回与神经重排：**采用BGE-M3生成1024维稠密向量和学习稀疏权重，在Milvus同一集合执行双路ANN并加权融合；与BM25词项检索并行，通过RRF合并候选，再用BGE-Reranker真实CrossEncoder重排Top-20候选、回取Top-5来源与父块上下文。
4. **证据约束与会话服务：**通过LangChain组织改写、检索及回答链，要求Qwen选择原文步骤并逐项验证引用ID与连续原文；结合租户／可见性过滤、MySQL来源复核和证据门槛，提供无依据提示与模型异常原文回退；使用Redis实现FAQ命中、答案与会话TTL缓存，MySQL持久化对话及演示工单。
5. **部署与可复现验收：**基于FastAPI提供问答、知识浏览和多格式上传接口，使用Docker部署独立MySQL／Redis／Milvus；为6GB显存环境实现模型依次加载释放及上传／检索互斥，保留逐题排名、API调用、原始失败和代码／语料哈希，分别测量分类、检索与完整模型回答。

## 项目成果

- **知识工程：**完成112份来源、592条知识单元及4,736条FAQ的实际入库；MySQL与Milvus记录数一致，向量抽样验证1024维稠密表示、非空稀疏权重和正文哈希，覆盖16类业务资料。
- **意图分类：**在432条分组留出的合成客服样本上，Accuracy为92.59%、Macro-F1为0.9265；训练集与留出集来源／模板／主题分组无交集。
- **检索效果：**在64道自建开发回归题上，真实神经混合检索＋重排Top-1为93.75%（60/64）、Hit@5为100%、MRR@5为0.9661；同语料基础BM25为71.875%、增强BM25为92.1875%，分别提高21.875及1.5625个百分点。
- **链路验收：**95项功能、契约及实际OCR／存储集成检查全部通过；8道Qwen端到端样例完成16次真实API调用，7道通过证据回答校验、1道触发原文回退，未命中答案缓存。

**16类是资料分类，不是接入16套企业业务系统。**112份资料、4,736条FAQ和24,000条模拟工单均为合成；FAQ与工单复用知识原文，没有增加独立事实。独立业务事实数未人工统计，不能写“80万真实企业知识”或“海量生产知识库”。

当前实现了稠密／学习稀疏混合检索、BM25并行召回、RRF和真实神经重排；没有实现HyDE、LoRA、RAGAS、企业身份认证、生产多租户授权或真实客服系统对接。BERT留出F1不应写为RAG问答准确率。没有真实业务上线、客服工作量下降或用户满意度提升的证明。

64题检索评测关闭Qwen；不能把其提升全部归因于Query改写。Top-1仍有4题未命中，较增强BM25只多命中1题，未证明统计显著性。24道负例中23道进入资料不足模式，1道返回“没有统一退款到账天数”的政策原文解释，不能写24/24严格拒答。检索P95为10.76秒，8题Qwen端到端P95为17.48秒，均包含模型加载／释放及真实服务访问，不是生产SLA。

BERT分类报告来自2026-09-30修订前合成语料；2026-10-01仅更新OCR手册，没有重新训练分类头。改写保护仅对部分编号、阿拉伯数字串和常见否定形式进行校验，没有证明所有语义约束完整保留。

历史词项检索59/64和HTTP P95=20.97ms属于旧基线，当前全栈以新的测量为准。数据、功能、失败与资源限制见 [FULLSTACK_VALIDATION.md](FULLSTACK_VALIDATION.md)，架构及组件职责见 [FULLSTACK.md](FULLSTACK.md)。
