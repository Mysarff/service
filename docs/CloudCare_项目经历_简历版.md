# CloudCare 云栈——企业客服 RAG 知识库问答系统

**项目性质：**个人工程项目，使用合成业务资料开发与评测

**技术栈：**Python、FastAPI、LangChain、Milvus、BGE-M3、BGE-Reranker、BERT、Qwen API、BM25／RRF、MySQL、Redis、RapidOCR、Docker

**项目地址：**[Mysarff/service](https://github.com/Mysarff/service)

## 项目背景

面向企业客服资料分散、用户问法多样及故障处理流程难以定位的问题，设计并实现企业客服RAG知识库原型。以账号权限、订单售后、订阅发票及开放接口等16类合成业务资料为样例，支持多格式资料入库、多轮问答、答案来源引用和演示工单留存，帮助用户定位处理依据，并为后续人工处理保留问题与会话记录。

## 项目职责与技术亮点

1. **知识库构建：**围绕16类客服业务资料，整理112份合成文档、592条带出处知识单元和4,736条FAQ；实现PDF、Office及图片解析与RapidOCR识别，新上传资料采用LangChain父子分块（父1200／子300／重叠50字符），保存来源、页码、版本及正文哈希，支持子块检索与父文回溯。
2. **意图识别与FAQ分流：**构建2,304条合成分类样本，以1,872条训练中文BERT三分类头，区分知识咨询、人工诉求和范围外问题；对FAQ问题建立BM25索引，沿用BM25→Softmax的0–1评分流程，通过阈值对照确定0.55保守试用门槛，结合出处有效性决定直答或进入RAG，记录候选、原始分、归一化分及分流原因。
3. **多轮查询理解：**结合服务端会话补全短追问，调用Qwen改写口语查询，对部分编号、数字及常见否定表达进行保留校验；同时保留原查询与改写查询参与召回，避免检索仅依赖一次改写结果。
4. **混合检索与精细重排：**采用BGE-M3生成1024维稠密向量及学习稀疏权重，在Milvus执行双路召回；与BM25词项检索并行，经RRF融合候选，使用BGE-Reranker重排Top-20、选取Top-5证据并恢复父块上下文。
5. **证据约束回答：**通过LangChain串联改写、检索与Qwen回答链，要求输出处理步骤及原文引用；复核来源范围与正文哈希，校验引用ID和连续原文，资料不足时拒答，接口或引用校验失败时回退到带出处的原文。
6. **服务集成与可靠入库：**基于FastAPI提供问答、上传、知识浏览和演示工单接口；MySQL单事务发布文档与父子片段，发布失败时按新增ID补偿清理向量，Redis提供FAQ版本管理和答案／会话TTL缓存；实现模型依次加载释放与推理互斥，适配本机6GB显存。

## 项目成果（2026-10-02复测）

分类、神经检索与Qwen数字先在BM25→全库Softmax→0.85版本实测；随后依据FAQ对照将默认门槛调整为0.55，新增专项检查。评测使用合成资料与开发回归题，分类、出处检索和模型引用检查分别统计。

- **知识工程：**完成112份来源、592条知识单元及4,736条FAQ的实际入库；MySQL与Milvus记录数一致，向量抽样验证1024维稠密表示、非空稀疏权重和正文哈希，覆盖16类业务资料。
- **意图分类：**复测当前BERT分类头，在432条分组留出的合成客服样本上Accuracy为92.59%、Macro-F1为0.9265；1,872条训练样本与留出集分组无交集。
- **检索效果：**在64道自建开发回归题上，真实神经混合检索＋重排Top-1为93.75%（60/64）、Hit@5为100%、MRR@5为0.9661；同语料基础BM25为71.875%、增强BM25为92.1875%，分别提高21.875及1.5625个百分点。
- **链路验收：**0.85版113项功能、契约及实际OCR／存储集成检查全部通过；调整0.55门槛后20项FAQ专项通过，验证门槛两侧分流与缓存失效。此前8道Qwen端到端样例完成16次真实API调用，6道通过证据回答校验、2道触发原文回退，答案缓存命中0次。

**16类是资料分类，不是接入16套企业业务系统。**112份资料、4,736条FAQ和24,000条模拟工单均为合成；FAQ与工单复用知识原文，没有增加独立事实。独立业务事实数未人工统计，不能写“80万真实企业知识”或“海量生产知识库”。

当前实现了稠密／学习稀疏混合检索、BM25并行召回、RRF和真实神经重排；没有实现HyDE、LoRA、RAGAS、企业身份认证、生产多租户授权或真实客服系统对接。BERT留出F1不应写为RAG问答准确率。没有真实业务上线、客服工作量下降或用户满意度提升的证明。

64题检索评测关闭Qwen；不能把其提升全部归因于Query改写。Top-1仍有4题未命中，较增强BM25只多命中1题，未证明统计显著性。0.85测量时24道负例中23道进入资料不足模式，1道返回“没有统一退款到账天数”的FAQ原文警示，不能写24/24严格拒答；该次神经检索P95为14.72秒，包含模型加载／释放与真实服务访问。Qwen小样本时延详见本轮评测说明，不是生产SLA。

BERT在2026-09-30的合成资料上训练，本次对原432条留出样本重做推理，未重新训练分类头；10月1日仅更新OCR手册。改写保护仅对部分编号、阿拉伯数字串和常见否定形式进行校验，没有证明所有语义约束完整保留。

**FAQ当前限制：**64条自然开发正例上，0.85门槛仅直答1题且命中错误步骤；调整0.55后4题达到门槛、3题来源正确，仍保留AI文章发布审核→搜索故障的高分错误，60题交给RAG。20道新挑战题均低于门槛，其中8道资料缺失事实没有被FAQ直答。0.55已参考这些诊断结果选择，不是独立盲测或最优值。原0.85实际回答路径的63/64返回来源覆盖及4,736原样FAQ的99.92%通过率保留为该配置记录，均不等于回答准确率或自动解决率。

原32.0诊断和未完成检索快照保留；原95/95、7/8和10.76秒均为10月1日历史数字。本轮命令、失败与资源限制见 [RESUME_EVAL_20261002.md](RESUME_EVAL_20261002.md)，架构与组件职责见 [FULLSTACK.md](FULLSTACK.md)。
