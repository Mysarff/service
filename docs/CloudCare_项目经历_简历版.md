# CloudCare 云栈——企业客服 RAG 知识库问答系统

**项目性质：**个人工程项目，使用合成客服资料开发与评测。

**技术栈：**Python、FastAPI、LangChain、Milvus、BGE-M3、BGE-Reranker、BERT、Qwen API、BM25／RRF、MySQL、Redis、RapidOCR、RAGAS、Docker。

**项目地址：**[Mysarff/service](https://github.com/Mysarff/service)

## 项目背景

面向企业客服资料分散、用户问法多样及故障处理步骤难以定位的问题，设计并实现客服知识库问答原型。以账号权限、订单售后、订阅发票及开放接口等16类合成业务资料为样例，串联资料入库、多轮咨询、混合检索、证据回答与演示工单留存，为后续人工跟进保留问题和会话记录。

## 项目职责与技术亮点

1. **知识库构建与溯源：**整理112份合成文档，构建592条带出处知识单元与4,736条FAQ问法；接入PDF、Office及图片解析和RapidOCR，新上传资料采用父1200／子300／重叠50字符分块，保存来源、页码、版本及正文哈希，实现子块检索和父文回溯。
2. **意图识别与FAQ分流：**基于2,304条合成样本训练并评测BERT客服三分类头；建立FAQ问题BM25索引，采用查询参考分归一化和可配置门槛，结合来源有效性决定直答或转入RAG，记录原始分、参考分、归一化分及分流原因。
3. **多策略查询理解与改写：**融合服务端历史会话，调用Qwen完成口语改写、子查询分解及关键词扩展，引入HyDE假设文档辅助稠密召回；结合字符规范化去噪与编号、数字、常见否定约束校验，保留原查询参与召回和重排，将单次规划限制为最多3个子查询、7条查询路径，对无效策略单独降级，避免错误改写覆盖原意。
4. **混合检索与精细重排：**基于BGE-M3生成1024维稠密向量和学习稀疏权重，在Milvus执行双路召回，并行融合BM25词项检索，通过带权RRF合并候选；使用BGE-Reranker重排Top-20候选，选取Top-5证据并恢复父块上下文，保留来源和访问范围校验。
5. **证据约束与服务集成：**通过LangChain组织改写、检索及Qwen回答链，校验回答引用与实际可见原文，HyDE仅用于检索；基于FastAPI提供问答、上传和演示工单接口，MySQL事务发布资料，Redis维护FAQ版本及答案／会话缓存，采用模型依次加载释放机制适配本机6GB显存。
6. **量化评测与回归：**接入RAGAS 0.4.3，使用实际问题、回答、生成时可见上下文和来源参考答案，分别评估忠实度、答案相关性、上下文精确率及召回率；开展单次改写与多策略改写的同题对照，记录调用次数、引用校验、耗时及缺失事实拒答，保留未提升和失败结果。

## 项目成果

- **知识工程：**112份来源、592条知识单元和4,736条FAQ实际入库；1,182条模板问法替换为基于原文生成的自然问法，答案和知识量保持一致。
- **意图分类：**当前BERT分类头在432条分组留出的合成样本上Accuracy为92.59%、Macro-F1为0.9265；该项沿用已有分类评测，本轮未重新训练。
- **真实查询对照：**12道自建题、两种策略共24次真实问答，最终24次回答均通过输出／引用结构校验；11道有依据问题的两组Hit@5均为100%，全部指定来源覆盖率均为90.91%（10/11），未观察到检索指标提升。多策略组12次规划均完成，部分不合格策略被过滤。
- **RAGAS与工程验证：**最终多策略组12道自建题的忠实度0.9333、答案相关性0.6568、上下文精确率0.8019、上下文召回率1.0000；130项功能及集成检查全部通过。口径与FAQ取舍见[本轮报告](QUERY_RAGAS_UPGRADE_20261002.md)，这些分数不等于业务解决率或综合准确率。

## 面试口径

- 一次Qwen规划可产生多种检索文本，通常另有一次回答调用。关键词仅走BM25，HyDE仅走稠密检索；原查询、改写及子查询走混合检索。最多7条查询文本不等于7次底层搜索。
- 当前FAQ门槛**0.60**用于“BM25原始分÷同查询参考BM25分”并截断至[0,1]的分数，不是60%正确率，不能与旧Softmax的0.55／0.85直接比较。
- 门槛是挑战题检查后的保守工作点：88道已知回归题仅1题FAQ直答且出处正确，20道挑战题均转RAG。FAQ覆盖低，不能宣称高拦截率或全局最优阈值。
- 旧版64题Top-1 93.75%、MRR@5 0.9661保留在evaluation/resume_eval_20261002，不能写成新增策略带来的提升。
- 16类主题不是16个真实系统；两种向量仍是592条知识单元；24,000条模拟工单不计知识量。
- 样例库保留的多模态来源文件为0，解析与OCR能力通过独立样例检查。不能写80万知识单元或大量真实多模态业务数据。
- BERT训练分类头；Qwen通过API调用，未进行LoRA微调。RAGAS裁判和回答使用同一模型服务，存在同模型偏差。
