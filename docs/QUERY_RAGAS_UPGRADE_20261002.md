状态：实现、真实模型对照与RAGAS评分已完成。开始版本：787308eb1917b4b31d639085ff840d24fd1f05eb。

## 本轮范围与验收口径

- 将历史会话融合、查询去噪、子查询分解、关键词扩展、HyDE接入实际RAG路径，保留原查询、控制检索预算并记录策略轨迹。
- 修正FAQ同答案多问法竞争与模板问法问题。BM25继续作为FAQ评分基础；对照旧算法，按预先写明的目标在开发集选择归一化阈值，再报告留出表现。
- 接入真实RAGAS评测，记录问题、实际回答、实际上下文、参考答案及其来源；分别报告Faithfulness、Response Relevancy、Context Precision和Context Recall。
- 运行有针对性的功能检查、真实模型链路及对照；保留失败和未提升的结果。更新简历与GitHub，以实测结果替换旧版本数据。

原教育/eud只读。知识资料仍为合成客服演示资料；不以增加重复数据扩大知识量。预期收益在测评完成前均不作为项目成果。

## 评测约束

1. 原64+24题保留为已参与开发的回归集；不得作为全新盲测。
2. 新建来源可追溯的开发/留出问题并保存文件哈希；FAQ生成只读取知识来源，不传入评测问句。
3. FAQ阈值目标优先约束误直答，再最大化正确直答覆盖；未达到目标时明确记录，不将最高分称为最优阈值。
4. Query策略使用同一模型、语料和候选预算对照；单独记录检索指标、调用次数与耗时。
5. RAGAS属于模型辅助判断。生成器与裁判若使用同一服务，标注相应偏差；解析失败不填0或1伪造结果。

**执行偏差：**本轮最终使用原有已知开发／留出／挑战题进行探索，没有形成全新的独立盲测。FAQ生成只读取来源，没有读取评测问句；但归一化方式和最终门槛参考了已知挑战结果，因此所有FAQ效果均按开发诊断报告。

参考：[RAGAS Faithfulness](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/faithfulness/)、[Response Relevancy](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/answer_relevance/)。

## 实际落地与边界

1. 原来的“多轮查询理解”只有历史补全与单次改写，原问题和改写问题一同召回。现在可称为**多策略查询理解与改写**：字符规范化去噪、历史融合、Qwen改写、最多3个子查询、关键词扩展、HyDE已进入实际代码路径。
2. 原问题、改写和子问题使用Milvus稠密／稀疏与BM25；关键词只走BM25；HyDE只走稠密检索。最多7条查询文本，子问题共享一组RRF权重；最终用原问题重排20个候选，返回5个证据片段。针对模型未主动分解的问题强化了规划提示，并对明确分隔、各自包含独立问法的并列诉求增加规则兜底；最终4道复合题均实际触发2条Qwen子查询。
3. 非法改写保留原问题；扩展凭空加入具体数字时单独过滤。约束检查覆盖部分编号、数字及常见否定表达，不是完整语义等价证明。Hypothetical passage从不进入知识库，也不直接作为回答证据。
4. 修复父文回填后章节ID与检索容器ID不一致、模型带方括号引用ID的问题。仅允许在实际可见父文对应章节内验证原文后映射到返回来源；未知ID、非原文内容及截断后不可见内容仍拒绝。
5. 112份合成文档、592个知识单元保持不变。FAQ仍为4,736条，其中1,182条模板问法替换为只依据来源生成的自然问句；112批生成资料全部通过结构和数字约束，不能等同于人工逐条语义审核。

## FAQ：为什么不是0.55或直接沿用0.85

旧Softmax只衡量候选间分数集中程度，可能把一个错误候选打成高分。原先同答案的8种问法还会互相竞争。此次保留旧算法与同答案分组Softmax作为诊断，实际门槛采用：

`归一化分 = min(1, BM25(问题, 最佳FAQ问句) / BM25(问题, 问题自身))`

分母使用同一个FAQ语料的IDF、平均长度和BM25参数（k1=1.2、b=0.75），未在语料出现的查询词也进入参考分。它是查询参考分归一化，并非正确率，也不与旧Softmax数值等价。

| 版本／门槛 | 88道已知回归题 | 20道已知挑战题 | 结论 |
|---|---|---|---|
| 新归一化0.37 | 直答6题，6题来源命中 | 直答15题，其中8题询问资料缺失事实 | **否决**，主题相似不代表能回答具体事实 |
| 最终0.60 | 直答1题，1题来源命中；其余87题交RAG | 全部交RAG，8道缺失事实题未被FAQ放行 | 保守工作点，FAQ覆盖率低 |

0.60高于这些已知缺失事实负例的最高分0.5772，并留出少量余量。该值参考过挑战题，是探索后的运行配置，**不是独立测试集上的最优阈值，也不证明未来不会误匹配**。开发集95%精确率目标无法与较高自然问句覆盖率同时满足，因此没有报告“最优阈值”或高FAQ拦截率。后续需要更多人工核验的问答与难负例。

文件：faq_calibration、normalization_experiment、tokenizer_calibration保留失败方案；faq_rejected_037保留被否决结果；faq_final验证真实Redis与文件评分一致。

## 同题真实RAG对照

模型：配置的Qwen API `qwen3.7-flash`；本地BGE-M3、Milvus、BGE-Reranker；同一592片段语料，Top-20→Top-5。为控制变量，此对照绕过FAQ与答案缓存，专门测RAG策略。12题包括单问题、多诉求、历史追问、格式噪声和缺失事实；全部是自建开发题。

| 指标 | 单次改写 | 多策略改写 |
|---|---:|---:|
| 问题数 | 12 | 12 |
| 规划成功（允许单项过滤） | 11/12 | 12/12 |
| 回答通过输出／引用校验 | 12/12 | 12/12 |
| 有依据问题Hit@5 | 11/11 | 11/11 |
| 全部指定来源均命中Top-5 | 10/11 | 10/11 |
| 指定来源平均召回率 | 95.45% | 95.45% |
| Qwen调用数 | 24 | 24 |
| 每题平均耗时 | 13.67秒 | 15.95秒 |

这些耗时包括本机模型依次加载释放，不是生产P95或并发压测。两组检索指标持平，不能宣称新增机制显著提升命中率。多诉求在子片段ID统计上可能缺一个ID，但父文实际包含该章节，因此另行保存生成可见上下文并用RAGAS评估。缺失的密码重置有效分钟数在两组均明确拒答。

首次对照的生成通过数为6/12和9/12，保存在query_results；引用修复后全量重跑保存在query_results_final。随后发现复合题未实际产生子查询，强化提示并增加兜底后，重新完整运行12题多策略，保存在query_results_current；本表单次改写基线复用query_results_final中对应12题记录，没有重新抽样或挑选基线。前述失败和中间版本全部保留。

## 真实RAGAS结果

RAGAS **0.4.3 collections API**，Qwen作为裁判，本地BGE-M3为答案相关性提供向量；最终多策略12份问答全部重新评分，基线复用之前12份实际问答评分，每项合计24/24有效，无以0或1填补解析失败。输入包括实际生成可见原文，不包含HyDE假设文字；参考答案与来源随题保存。

| RAGAS指标 | 单次改写（12题） | 多策略（12题） |
|---|---:|---:|
| Faithfulness 忠实度 | 0.8917 | **0.9333** |
| Answer Relevancy 答案相关性 | 0.6449 | **0.6568** |
| Context Precision 上下文精确率 | 0.7833 | **0.8019** |
| Context Recall 上下文召回率 | 0.9722 | **1.0000** |

裁判与回答使用同一模型服务；只有12道自建题、单次评分，微小差异不构成显著提升证明。答案相关性约0.66仍有改进空间。拒答题也纳入平均，因此不能把该分数称为“综合准确率”。最终逐题结果见ragas_current，基线和中间版本见ragas_results。多策略平均耗时增加约2.28秒，当前数据不能证明这部分开销换来了检索指标提升。
