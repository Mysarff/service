## 检索、Qwen 与功能检查

完整检索评测固定 64 道有出处问题、24 道无依据／越界问题。基础 BM25、增强 BM25 与神经混合检索使用同一语料、同一标签；Top-1、Hit@5、MRR@5 按来源 ID 计算，完整逐题排名与失败保留。题目参与过开发调试，属于开发回归，不能称独立盲测。

Qwen 的 8 题检查另行记录真实 API 调用次数、改写、答案模式与原文引用验证。匹配兼容换行／空格差异，展示时还原为对应出处的真实连续原文；非空白文字、数字、否定内容的变更仍会被拒绝。引用有效不证明回答完整或业务政策真实；无依据、接口失败或引用不合法时明确拒答或返回资料原文。没有开展 RAGAS、生产用户满意度或客服降本评估。

功能报告 `evaluation/fullstack_tests.json` 区分注入组件的接口／契约检查、真实数据库集成和真实 OCR。单元测试中的假组件只用于测试边界与异常，不能当作真实模型质量测量。

## 环境与耗时

本机 Windows、Python 3.11.15、RTX 3060 Laptop 6 GB；PyTorch 2.12.0+cu126。由于早期双大模型同时驻留发生 Windows OS1455／内存映射失败，默认采用 `model_memory_policy=sequential`：BERT、BGE-M3 和重排器依次加载释放，同一实例的检索和上传共享推理锁，查询向量缓存保留。

每次权重重载的成本计入实测请求延迟；不能称常驻热模型性能，也不能沿用旧 BM25 的毫秒级 HTTP 数字。更大显存、更多内存的机器可配置 `resident`，需要重新测量。本次未修改系统分页设置、未停止用户其他模型服务。

最终冻结代码的64题神经检索平均9.6227秒、P50=9.4363秒、P95=10.7622秒、最大12.1545秒。8题Qwen端到端平均8.8777秒、P50=7.6202秒、P95=17.4774秒；小样本P95等于该组最慢请求，不能作为稳定服务承诺。两组运行顺序及查询向量缓存状态不同，不能比较后宣称生成更快或缓存带来确定加速比例。

最终代码重新启动后，在网页实际提交“登录密码忘记了，注册邮箱还能收信，应如何重置？”，返回模型结合知识库回答、引用ACC-13，界面计时19.0秒。该单次冷进程演示不与8题预热测量混算，截图为 `docs/screenshot_fullstack.png`。

Query改写的约束检查覆盖ASCII编号、阿拉伯数字串及若干常见否定表达，未证明所有否定形式或中文数词都能保真。规则上下文补全只处理词项较少的短追问；较长追问依赖Qwen的历史改写，不能承诺规则层自动补全所有省略信息。

## 已处理的问题与边界

- 原先词项检索版缺少完整神经与数据库链路，当前以真实组件实现替换默认入口，并保留 `baseline_app.py` 供历史结果复现。
- 新版 Transformers 与原 FlagReranker 的旧分词调用不兼容，改用同一真实 BGE 重排权重的 Transformers CrossEncoder 推理；不是用启发式分数替代模型。
- 初始 Qwen 回答存在“引用 ID 正确但细节无出处”的问题。当前要求输出原文步骤，校验引用和连续子串；这是受约束的证据选择，没有证明自由生成问答准确率。
- 新上传TXT实际验收曾因模型合并换行而触发原文回退。原始失败及诊断响应保存在 `fullstack_workflow_attempt1.json`、`attempt2.json`；修复后允许空白差异匹配，并将输出还原为原文连续区间，字词、数字或否定修改仍拒绝。
- 知识发布对向量失败进行精确新 ID 清理，SQL 文档／父子块同事务发布。跨 MySQL 与 Milvus 没有分布式事务；进程崩溃仍可能留下未发布向量，检索时跳过无 MySQL 正式来源的记录。
- 网页固定演示租户、公开资料、本机访问；租户字段过滤和来源复核不等于企业认证或完整多租户授权。人工工单仅落本地数据库，没有连接真人客服或执行真实订单操作。

## FAQ BM25调整与验收状态

FAQ阶段改为对已发布的问题使用BM25（k1=1.2、b=0.75）检索，按Top-1原始分数判断：达到阈值且关联出处通过业务分类、租户及可见性核验时，直接返回该FAQ与出处；低于阈值、没有候选或出处无效时，继续进入RAG。标准化完全匹配也需要通过相同阈值，不再依靠精确匹配捷径或Dice相似度决定直答。

配置项为`Settings.faq_bm25_threshold`，环境变量为`CLOUDCARE_FAQ_BM25_THRESHOLD`，INI字段为`[faq] bm25_threshold`。默认`8.0`是未经阈值标定的启动配置；BM25分数随查询词、语料和分词变化，不是0–1概率，也不与旧版0.85／0.98相似度阈值互换。

真实Redis保存FAQ记录和发布版本，各工作进程按Redis版本构建本地BM25快照，兼容已有records索引。Redis并未运行BM25模型。答案缓存键同时包含FAQ版本和阈值；`trace.faq`记录`score`、`threshold`、`accepted`、`reason`和`index_version`，供追踪直答或进入RAG的原因。

本轮未新增或运行测试，没有重新执行10月1日的完整检索、Qwen和延迟评测。因此本页95/95、60/64、7/8及对应延迟均为历史结果，不能归因于本次FAQ修改；FAQ直答率、误答率、阈值选择和性能收益尚未测量。
