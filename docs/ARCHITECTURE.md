# 与教育 RAG 的关系

两个项目共享“整理知识→切分→检索→组织上下文→回答”的基本思路，但当前代码不是原教育版的完整迁移。

| 环节 | 教育版源码中的设计 | 本客服项目已实现 |
|---|---|---|
| 业务资料 | 教育FAQ、课程资料 | 16模块合成企业服务手册、客服FAQ与模拟工单 |
| 文档处理 | 多格式、OCR、父子块 | 生成手册按章节切分；用户TXT/MD分段并保留尾部；父ID仅作溯源 |
| 查询分类 | 训练的BERT和策略选择 | 可读的模块关键词规则、实时数据与缺失政策拦截 |
| 检索 | BGE-M3稠密/稀疏 + Milvus | 内存BM25词项检索 |
| 排序 | BGE-Reranker模型 | 标题与模块加权，无神经重排器 |
| 查询扩展 | HyDE、子查询、回溯等 | 未实现；只有少量短追问携带前一问题上下文 |
| 回答 | Qwen生成、流式返回 | 兼容模型HTTP接口、非流式返回、引用ID检查与原文回退 |
| 存储 | MySQL、Redis、Milvus | JSONL资料与内存索引；运行工单本地JSONL |
| 对话 | 数据库历史 | 当前浏览器会话的最近两轮，不含长期记忆 |
| 验证 | 原教育项目自己的检查 | 独立的接口检查、三种词项排序对照、44题开发回归 |

不能因为新项目运行成功，就说它复现了BGE、Milvus、HyDE，或继承了教育版的评测结果。原BERT的教育标签不适合直接用于企业业务意图，需要新标签与真实标注数据后再训练和比较。

若需要恢复原版完整技术栈，应在这个独立仓库新增向量编码、独立Milvus集合和重排组件，再与当前BM25基线在同一业务测试集上比较。使用独立数据库和集合避免覆盖教育版的索引。本次没有部署这些组件，也没有修改原教育服务或GitHub仓库。

## 当前模块分工

`engine.py`负责索引构建、查询、证据门槛、模型调用和资料导入。`app.py`负责HTTP协议和本地工单。前端显示回答的实际模式及来源全文。模拟工单不进入知识索引；它们只用于资料完整性与流程演示。

引用ID校验只验证“ID属于本次检索结果”，不能证明每个句子都被原文支持。词项覆盖率是启发式门槛，不是概率。当前源码需逐步模块化、补权限和外部业务接口后才适合企业上线。
