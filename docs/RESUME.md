# 简历项目与指标证据

完整项目名称、背景、技术栈、职责及量化成果见 [CloudCare_项目经历_简历版.md](CloudCare_项目经历_简历版.md)。该稿对应当前真实神经检索与数据库版本；历史词项版简历和数据保留于 evaluation/resume_refresh_20260930/。

## 可写与应解释的数字

- 112份合成文档、592条检索知识单元、4,736条FAQ：从文件与实际MySQL／Redis／Milvus查询核验。FAQ和24,000条模拟工单复用来源资料，不增加独立事实。
- 2,304条合成客服分类样本：训练1,872条，分组留出432条。冻结BERT骨干、训练三类分类头，留出Accuracy=92.59%、Macro-F1=0.9265；仅是意图分类结果。
- 64道有出处问题＋24道无依据／越界题：完整检索报告为 evaluation/fullstack_metrics.json。Top-1、Hit@5和MRR@5按来源ID计算；属于开发回归，不能称真实客服准确率。
- 当前全栈Top-1=60/64（93.75%）、Hit@5=64/64、MRR@5=0.9661；同语料增强BM25=59/64，提升1.5625个百分点。23/24负例进入严格拒答模式，1例给出否定退款保证的资料原文。
- 完整功能套95/95通过；8题Qwen问答共16次真实API调用成功，7题通过证据回答校验、1题原文回退，不等于问答准确率100%。
- Qwen改写及证据原文选择：真实API、引用校验和回退分别记录。引用合法不等于事实正确，也没有RAGAS测量或生产满意度数据。
- 实际OCR、数据库集成与单元契约检查：见 evaluation/fullstack_tests.json。完整耗时包括模型加载释放，不能沿用旧词项基线的毫秒响应。

## 面试时应能讲清

1. Milvus同一行存储BGE-M3稠密与学习稀疏两种向量；592行仍是592个知识单元。
2. 神经混合召回先用WeightedRanker，和BM25候选再经RRF融合，最后CrossEncoder重排和父块补回；三个阶段作用不同。
3. 旧592条样例按章节和故障处理阶段组织；新上传资料使用LangChain递归父子切分，不能把旧数据全部说成新切分器产出。
4. BERT预测客服意图，Qwen负责改写和原文步骤选择；没有全量BERT微调、LoRA或HyDE实现。
5. 上传先写向量，再用MySQL单事务发布；失败精确清理新片段。跨库没有分布式事务，崩溃后未正式发布的向量会被来源复核跳过。
6. 本机6GB显存默认顺序加载模型；缓存保留查询向量，完整请求计入重载时间。更大机器常驻模型的性能需另测。
7. 当前网页固定演示租户、公开合成资料、本地工单，不是已上线真实企业业务。
